# Vaseball ⚾

ブラウザで遊べる野球ゲーム。現在は CPU (Bot) とのオフライン対戦に対応しています。
今後、別ホストのサーバーを介したリアルタイムオンライン対戦に対応する予定です。

## 遊び方

| 場面 | 操作 |
| --- | --- |
| 打つ | 黄色い円 (ミート位置) をマウス / 矢印キー / WASD で動かし、ボールが手元に来た瞬間にクリック / Space。スマホはボールの来る位置をタップ |
| バント | B キー (または画面下のボタン) を押している間バントの構え。ボールが来るまで押し続けるとバント、途中で離すとバットを引く |
| 投げる | 1〜6 キー (または画面下のボタン) で球種を選び、狙うコースにカーソルを合わせてクリック / Space。打者の体・頭も狙える |
| タイム | T キー (投球の合間のみ)。バットを持ち替えられる |
| リクエスト | 塁上のアウト・セーフ判定が不服なら、プレーの映像が流れている間に R キー |
| 音 | M キーでミュート切り替え |

- 打撃はタイミング (±100ms) とミート位置のズレで打球の質が決まります。早いと引っ張り、遅いと流し打ち。ボールの上を叩くとゴロ、下を叩くとフライになります。
- 投球の狙いには球種ごとのブレがあります。ボールの軌道は終盤に変化します。
- バントは打球が弱く、走者はスタートを切っているので送りバントになりやすい。2ストライクからのバントファウルはスリーバント失敗 (三振)。
- 頭部への死球: 直球なら即「危険球退場」。変化球なら警告試合となり、以後の頭部死球は球種を問わず退場。
- バット (性能は `core/src/bats.ts`):

  | バット | ミート範囲 | パワー | タイミング幅 | 振り出し | 特徴 |
  | --- | --- | --- | --- | --- | --- |
  | ふつうのバット | 0.5 | ×1.00 | ±100ms | 即 | 基準 |
  | トーピードバット | 0.44 | ×1.07 | ±100ms | 押して 0.1 秒後 | 芯は狭いが飛ぶ。ファウルになりにくい |
  | フライパン | 0.85 | ×0.82 | ±120ms | 即 | よく当たるが低い打球 |
  | 左折可の標識 (白い支柱つき) | 0.6 | ×1.13 | ±75ms | 押して 0.15 秒後 | 重い鉄製。打球が左へ曲がる (引っ張り方向 -14°) |

  振り出しが遅いバットは、押してから実際にバットが出るまでカーソルの周りにオレンジのゲージが溜まります。早めに押してください。

- CPU の打者は打席ごとに 4 種類のバットからランダムに選びます。
- 塁審 (一・二・三塁) は 5% の確率でアウト/セーフを誤審します (本塁は球審なので誤審なし)。
- リクエストは NPB に準拠: 9 回までに各チーム 2 回、判定が覆れば回数は減らない、延長戦は残数に関係なく新たに 1 回。対象は塁上のアウト/セーフ (ストライク・ボールは対象外)。
  リプレー検証では、正しい判定は必ず維持。誤審は映像で明らかなら (送球と走者の差が 0.08 秒以上) 必ず覆り、それより際どいと 60% の確率で覆ります。
  覆った場合の走者は「正しい判定だった場合」の位置に戻します (一塁セーフ誤審→アウトなら内野ゴロに、二塁封殺セーフ誤審なら野選に、など記録も付け直し)。
  CPU の監督も、不利な誤審には 80%、際どい正しい判定には 15% の確率でリクエストします。

## 開発

```sh
npm install
npm run dev        # http://localhost:5173
npm test           # core のテスト (ルール + Bot 同士の 200 試合シミュレーション)
npm run typecheck
npm run build      # packages/client/dist に出力
```

`main` に push すると GitHub Actions (`.github/workflows/deploy.yml`) が GitHub Pages にデプロイします。
リポジトリの Settings → Pages → Source を「GitHub Actions」にしてください。

## 構成

```
packages/
  core/     DOM 非依存・決定的なゲームロジック (クライアントと将来のサーバーで共有)
    pitch.ts     球種・投球生成・軌道
    bats.ts      バットの種類と性能
    batting.ts   スイング / バント判定 → 打球 (初速・角度・方向)、死球 (頭部含む)
    umpire.ts    塁審の判定 (誤審)・リクエストのリプレー検証
    fielding.ts  打球処理 (フライ捕球・ゴロ・併殺・内野安打・本塁打) とアニメーション用の軌跡
    rules.ts     カウント・進塁・得点・チェンジ・サヨナラ・延長
    bot.ts       CPU の投球 / 打撃判断
    rng.ts       シード付き乱数
  client/   Vite + Canvas の Web クライアント
    game/        試合進行 (session) / 入力 / コントローラ (Human・Bot)
    render/      捕手視点の投球画面・俯瞰フィールド・HUD
    audio.ts     BGM・効果音 (Web Audio で合成、音声ファイルなし)
```

### オンライン化の方針

1 球のやり取りは「投手の入力 (`PitchInput`)」と「打者の入力 (`SwingInput`)」の 2 つだけです。

1. 投手クライアント → サーバー: `PitchInput` (球種・狙い)
2. サーバー: `createPitch` で実際の投球を確定し、リリース時刻とともに両者へ送信
3. 打者クライアント: 受け取った投球をローカルで再生し、**リリースからの経過時間** で `SwingInput` を送信 (通信遅延がタイミングに影響しない)
4. サーバー: `resolvePitchEvent` → `applyPitchEvent` で結果を確定し、両者へ配信

乱数はサーバーが持ち、`core` をそのまま使って権威的に判定します。クライアント側は
`PitcherController` / `BatterController` に Remote 実装を追加するだけで同じ試合進行を使えます。
